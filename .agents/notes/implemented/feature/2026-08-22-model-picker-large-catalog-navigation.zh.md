# Agent Note: 大目录下的模型选择器导航

Status: implemented

[English](2026-08-22-model-picker-large-catalog-navigation.md) | 中文

## Problem

composer 的模型面板把已公布目录渲染成一条按提供方分组的滚动列表，而该 slot 是会话级切换模型的唯一入口。对于只运行一两条手写路由的部署，这样读起来没问题——面板建成时，所有随附组合正是如此。pi-ai 网关路由改变了量级：命名某个已安装目录提供方的路由会服务该提供方的整份目录，仅 OpenRouter 就公布 276 个模型。此时要找到某一个，就得在高度上限 360px 的卡片里滚动约三百行，而唯一的路标只有提供方标题。

## Decision

模型面板获得两条穿越大目录的路径：分组列表上方的文本筛选，以及可把自身模型折叠起来的提供方标题。

### 筛选

面板在分组列表上方渲染一个文本输入框，列表只显示与查询匹配的内容。

查询按空白切分，每个词都必须命中同一行，该行才会保留。一行的可搜索文本包括其提供方的 id 与名称，以及模型自身的 id、名称和说明，比较时不区分大小写。除显示名称外还匹配 id，正是这一点让模型在目录渲染出另一个名称时，仍能用其提供方文档里的 id 找到——`gemini-3-flash` 能找到 `Google: Gemini 3 Flash`；而匹配提供方字段则让路由名把面板收窄到该路由。要求每个词分别命中、而非整串匹配，使 `gemini flash` 能够找到 `Google: Gemini 3 Flash`，子串匹配则会漏掉它。

该筛选只影响显示：它在已常驻的目录之上收窄当前打开面板的渲染内容，绝不向宿主发起查询，因此已公布集合、选择约定与 `session.selectModel` 都保持不变。模型全部落选的分组不再渲染标题；无任何匹配的查询会渲染一条写明该查询词的专属文案，这与"目录本身没有模型"是两个不同事实，因此也是两条不同文案。

查询词只属于面板的一次访问。进入面板时列表完整、输入框获得焦点；离开面板或关闭菜单即丢弃查询，使得后续访问绝不会打开一个被看不见的筛选悄悄收窄的列表。在输入框中按 ArrowDown 会进入列表的第一行，因为菜单原有的循环移动逻辑从当前持有焦点的条目算起，而光标停在输入框时没有任何条目持有焦点。

### 折叠分组

每个提供方标题不再是静态文本，而是该分组的展开／折叠控件：按下折叠该分组的模型，再按一次恢复。标题始终渲染，因为它就是恢复的入口；标题同时显示所含数量——那正是折叠后本会被隐藏的事实，在查询生效时则是匹配数。标题也加入菜单的方向键顺序，因此从筛选框按 ArrowDown 到达的第一行就是第一个分组的标题。

与查询不同，折叠会跨越面板的多次访问。把一条 276 个模型的路由收起来，是针对该部署中一个吵闹分组的长期偏好，因此重新打开菜单时它仍是折叠的；而查询只是一次查找，让下一次访问从查询状态里开始，会隐藏面板从不解释的模型。

查询生效时会覆盖折叠：所有匹配分组一律展开渲染，且折叠不被清除，只在查询存在期间被忽略。否则，答案恰好落在折叠分组里的搜索会报告"无结果"，那比没有搜索更糟。

## Alternatives considered

**通过宿主筛选。** 把查询传给 `session.models` 的方案被否决：目录已经常驻，并与 `/model` 入口共享，因此每次按键往返一次并不换来任何正确性，反而让面板内容依赖连接状态——而该 slot 的其余部分都不依赖它。

**只匹配显示名称。** 否决，因为目录渲染的名称与提供方文档里的 id 经常不同，而用户在提供方文档、配置和会话日志中读到的正是 id。只匹配名称会让模型无法用其使用者唯一知道的字符串找到。

**整串子串匹配。** 否决：当模型名称在用户键入的词之间夹着版本号或厂商段时它恰好失效，而网关目录大多如此。

**超过一定行数才显示筛选框。** 否决，因为这个阈值是无人负责的臆造常量，而且一个在某些路由出现、在另一些路由消失的控件，会让面板行为对使用者变得不可预期。

**改为虚拟化列表。** 作为本问题的答案被否决：它让三百行渲染得更便宜，却没让其中一行更容易被找到。它作为渲染开销的手段仍然可用，那与"找到一个已知模型"是两件事。

**默认折叠所有分组。** 否决：那会让首次打开的面板只剩一排标题；而只有一条小路由的部署——所有随附组合至今仍是如此——还得多按一次才能看到本来就直接展开的列表。

**查询开始时清除折叠。** 否决，改为忽略：清除意味着折叠会在一次无关的搜索之后悄悄消失，用户收起来的分组没被要求就自己回来了。

**把折叠持久化到用户设置。** 因缺少当前消费者而否决：该 slot 只为它所属的会话持有这一状态，目前没有任何需求要求该偏好跨重新加载存活。做成设置分节需要 schema、命名空间和一次宿主往返，而这份偏好还没有人要求保留。

## Consequences

该 slot 面向宿主的行为没有变化，因此没有任何会话事件、wire 字段或持久事实发生位移；这是一个客户端本地的渲染决策，目录仍是所供集合的唯一来源。

筛选会在每次按键时基于常驻分组重新推导。在目录规模下这是一次数组遍历，且 `useMemo` 以分组与查询为键，因此无关的目录刷新不会触发重算。折叠的分组根本不渲染任何选项行，而非渲染后隐藏，因此其模型也一并离开方向键顺序。

标题现在是一个控件，因此分组的 `aria-labelledby` 指向一个按钮，其可访问名称包含分组名称与数量，折叠状态则由该按钮上的 `aria-expanded` 承载。

`ModelSelect.tsx` 位于 `vitest.config.ts` 的客户端 GUI 覆盖率豁免中，因此新增分支由该包的 jsdom 套件负责，而非逐文件覆盖率闸门。

`/model` popupSelect 入口保留自己的呈现方式，不在本决策范围内；通过该入口访问大目录的部署仍然需要滚动。

## Testing

`packages/client/ui-model-selection/tests/model-select.client.spec.tsx` 覆盖了空查询与收窄后的对比、按提供方名称／模型 id／说明匹配、每词必中规则（含各词分别命中不同行的查询）、无匹配文案与空目录文案的区分、进入时的焦点与 ArrowDown 进入列表、离开面板时丢弃查询，以及选中筛选后剩下的那一行。

折叠部分覆盖了一次标题按下及其反向操作、两个分组各自独立折叠、折叠跨面板访问存活而查询不存活、查询生效期间折叠分组的匹配项照常渲染并在查询清空后恢复折叠，以及查询生效时数量显示匹配数而非目录总数。
